# 에셋 현지화 제작

이 스킬은 원본 분석부터 레이어 생성·조립·보관·검수까지 이어지는 제작 절차다. 분석과 시각 판단은 에이전트가, 파일 보관과 합성 검증은 로컬 CLI가 맡는다. 이미지 생성 도구는 현재 환경에서 실제 사용 가능한 것을 선택하고 해당 도구의 지침을 따른다. CLI 자체는 생성 API를 호출하지 않는다.

## 생성 전에

1. 원본을 직접 보고 번역 문구와 근거를 확인한다. `layer-studio init <source.png> <job> --asset <id> --locale ko`로 원본 바이트를 보존한다.
2. `작업기록/analysis.json`과 밝은/어두운 배경 미리보기를 확인한다. 실제 알파, 반투명 영역, 가장자리 잘림, 배경·그림·텍스트·효과를 구분한다. 전체 대표색만으로 레이어 색상을 결정하지 않는다.
3. `references/analysis-example.json` 형식을 참고해 레이어별 근거, 색 범위, bbox, 외곽선 두께, 불투명도, 효과 파라미터를 작성한다. 흰색 중심과 유색 광택을 평균색으로 합치지 않는다. PNG에서 추론한 계층임을 명시하고 원래 PSD를 복원했다고 말하지 않는다.
4. 바닥→위 레이어 순서와 재사용·생성·후처리 계획을 정한다. 단순 글씨 1회, 그림+글씨 2회, 복잡한 메뉴 4~5회는 견적 예시다. 레이어 수와 생성 횟수는 같지 않으며 재시도는 별도로 센다. 불명확한 부분을 기록하고 재시도 한도를 정한다.

## 픽셀 작업 경계

- 원본은 관찰·색/알파/bbox 측정·참조 이미지로 사용한다. 원본 픽셀을 코드로 잘라 레이어로 만들거나, 글씨를 지우거나 메우거나, 원본 알파를 생성물에 복사하지 않는다. 함수 이름이 아니라 실제 픽셀 출처로 판단한다.
- 그림과 글씨는 생성 도구로 만든다. 생성된 에셋의 배치·크기·색 보정·키잉·마스크와, 실측 파라미터 및 생성 레이어 알파에서 만든 그림자·외곽선·광택은 로컬 후처리로 처리할 수 있다. 사용 파라미터와 입력 출처를 남긴다.
- 기본은 실제 RGBA다. 체크무늬가 픽셀에 그려진 RGB 이미지를 투명 에셋으로 취급하지 않는다. 크로마키가 필요하면 해당 레이어에 적합한지 먼저 판단한다. 광택·연기 같은 반투명 효과를 이진 키잉으로 처리하지 않는다.
- 기존 생성물을 재사용할 때는 파일과 생성 이력을 함께 보존한다. 원본 컷아웃을 재사용 생성물로 등록하지 않는다.

## 생성과 보관

원본의 글씨 스타일을 참고하여 번역 글씨를 생성한다. 필요할 때 무텍스트 그림 → 프레임/배경/캐릭터 분리 생성 → 글씨 생성 순으로 진행한다. 모든 에셋에 같은 단계를 강제하지 않는다. hover/disabled 변형은 원본 상태별로 분석한다.

생성할 때마다 `references/attempt-example.json`을 작성하고 `layer-studio archive <job> <record.json>`으로 보관한다. 정확한 프롬프트, 백엔드, 모든 참조, 출력 원본, 재시도 관계를 남긴다. 실패 결과도 `rejected`로 보관한다. 실패 파일 위에 새 결과를 덮어쓰지 않는다. 각 기록은 한 번의 생성 호출과 한 개 출력에 대응한다. 여러 출력이 반환되면 원래 호출 관계를 별도 메모에 남기고 호출 수를 중복 집계하지 않도록 현재 CLI의 제한을 설명한다.

후처리 전 생성 원본을 유지한다. `L0_art`, `L1_<effect>_baked`, `L2_text_<locale>` 같은 역할 이름을 쓰되, 실제 쌓임 순서는 spec의 배열이 결정한다. 역할 번호가 z 순서를 강제하지 않는다.

## 조립과 PSD

`references/spec-example.json`대로 원본과 같은 캔버스의 레이어 PNG를 준비하고 `layer-studio build <job> <spec.json>`을 실행한다. v0.1 도구는 normal blend, opacity, visibility를 지원한다. 효과와 배치는 입력 PNG에 반영한다. 래스터 PSD이며 폰트 텍스트, 조절 가능한 효과, 별도 마스크를 자동 복원하지 않는다.

출력은 한 작업 폴더에 원본에셋, 레이어에셋, 통합에셋, PSD, 작업기록을 둔다. 생성 원본과 실패 시도도 자산이다. 동일 ID·revision은 덮어쓰지 않으며 부분 실패도 남긴다. ZIP은 기본 산출물이 아니다.

PSD를 다시 열어 캔버스·레이어 이름/순서·불투명도·가시성과 합성 결과를 확인한다. spec은 바닥→위, Photoshop 패널은 위→아래다. `layer-studio verify <job> <revision>`은 보관 파일 해시와 PSD를 재검사한다.

## 검수와 완료 보고

원본/후보를 밝고 어두운 바탕, 원본 크기, 실제 표시 크기에서 비교한다. 번역 정확성, 글씨 스타일·크기·줄바꿈·가독성, 원문 잔재, 체크무늬·키색·잘림, 캐릭터·프레임·색·효과 차이를 확인한다. 필요하면 텍스트 제외 마스크와 임계값을 명시하여 원본 일치도를 측정한다. 특정 게임의 임계값을 보편적인 품질 점수로 쓰지 않는다.

파일/PSD 검증, 시각 검수, 실제 게임 검수, 배포 승인을 구분한다. 미달 후보를 보관한 사실이 승인 근거는 아니다. 품질 리뷰는 새 기록으로 남기고 기존 qa.json을 고쳐 PASS로 만들지 않는다. 원본 컷아웃 금지는 해시만으로 증명되지 않으므로 처리 레시피도 검토한다.

완료 보고에는 폴더, 레이어 수, 실제 생성/재시도 횟수, PSD 검증, 시각 차이, 게임 적용 여부를 적는다. Steam/게임 설치 변경이나 개발사 전달·공개 업로드는 제작 요청만으로 수행하지 않는다.

CLI 설치·사용법은 저장소 README를 따른다. 스킬만 복사한 환경에서는 CLI 설치 여부를 확인하고, 없으면 같은 산출물 계약을 직접 구현하되 실행하지 않은 검증을 완료라고 쓰지 않는다.
